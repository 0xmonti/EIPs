## 1. Executive Summary & Core Objective

The `monti.bio` EVM engine and `0xmonti.net` network layer adopt **EIP-8268** to extend the Block Access List (BAL) mechanism defined in EIP-7928. By embedding per-account post-block storage trie roots into modified `AccountChanges` records, partially stateful nodes across `0xmonti.net` can independently construct and verify the global post-block state root without maintaining the full storage tries of every modified account.

---

## 2. `monti.bio` EVM Execution Specification

### 2.1 Modified `AccountChanges` Layout

For all block state transitions executed by `monti.bio`, every `AccountChanges` record containing non-empty state-change lists (`storage_changes`, `balance_changes`, `nonce_changes`, or `code_changes`) MUST include the trailing `storage_root` field.

```
StorageRoot = bytes32     # 32-byte trie root, OR empty byte string (0x80) if trie is empty

AccountChanges = [
    Address,
    List[SlotChanges],    # storage_changes
    List[StorageKey],     # storage_reads
    List[BalanceChange],  # balance_changes
    List[NonceChange],    # nonce_changes
    List[CodeChange],     # code_changes
    StorageRoot           # post-block storage trie root (EIP-8268)
]

```

### 2.2 Storage Root Encoding Rules

| Account State Post-Execution | `storage_root` Encoding | RLP Byte Representation | Validation Rule |
| --- | --- | --- | --- |
| **Non-Empty Storage Trie** | 32-byte Storage Trie Root | `0xa0...` (32 bytes) | MUST match exact trie root produced by `monti.bio` |
| **Empty Storage Trie** | Empty Byte String | `0x80` | Canonical root `0x56e81f...` MUST NOT be used |
| **Read-Only / Unchanged** | Omitted | N/A (6-field struct) | Retains standard 6-field layout from EIP-7928 |

---

## 3. `0xmonti.net` Network Consensus & Validation Rules

A block propagated across `0xmonti.net` is considered invalid and rejected by consensus peers if any `AccountChanges` entry violates the following constraints:

1. **Non-Empty Trie Mismatch:** The post-block storage trie contains key-value pairs, but `storage_root` does not match the 32-byte root evaluated post-block execution.
2. **Canonical Empty Violation:** The post-block storage trie is empty, but `storage_root` is encoded as the 32-byte canonical empty root `0x56e81f171bcc55a6ff8345e692c0f86e5b48e01b996cadc001622fb5e363b421` instead of `0x80`.
3. **Commitment Integrity:** The `block_access_list_hash` calculated by `monti.bio` engine API MUST incorporate `storage_root` into the RLP payload prior to signing or state root derivation.

## 4. Node State-Trie Leaf Assembly Matrix

Partially stateful edge nodes on `0xmonti.net` reconstruct the post-block state-trie leaf using the synthesized data matrix below:

```
+-------------------------------------------------------------------------------+

+-------------------+-----------------------------------+-----------------------+

+-------------------------------------------------------------------------------+
                                        |

                                        |

```

## 5. Backward Compatibility & Hard Fork Requirements

* **Fork Activation:** Implementation requires a coordinated hard fork across all `0xmonti.net` validator nodes and `monti.bio` runtime instances.
* **Engine API Modifications:** Clients communicating with `monti.bio` execution engines via Engine API MUST support the 7-field RLP serialization for modified accounts. Legacy EIP-7928 formats without `storage_root` will fail block verification post-activation.
